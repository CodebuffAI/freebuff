# opencode-server

A self-hosted, OpenAI-compatible gateway and dashboard for [opencode](https://opencode.ai),
preloaded with the Freebuff agents exported to `.opencode/agents/` in the repository root.

It runs on Cloudflare Workers (or locally with `wrangler dev`), talks to the AI providers **you
already have keys for**, and hands out its own client keys so your editor, phone or teammates can
use one endpoint instead of sharing a raw provider key.

## What it does

- `POST /v1/chat/completions`, `POST /v1/<any-openai-path>` — proxied to the right upstream,
  streaming included.
- `GET /v1/models` — the models you configured.
- Client keys (`sk-oc-…`) that you create, list and revoke; only their SHA-256 hash is stored.
- Optional per-key limits: requests/minute and monthly token budget. **Both default to none**, so
  a fresh key has no gateway-imposed cap.
- Usage metering per key, model and day.
- Dashboard at `/` for keys, usage, models and a ready-to-paste opencode config.
- The Freebuff agent definitions in `.opencode/agents/` (generated by
  `bun scripts/export-opencode-agents.ts`) work against any model the gateway serves.

This is a gateway over **your own** provider accounts. It does not create free access to a
provider's paid capacity, and it cannot exceed the quotas those accounts already have.

## Setup

```bash
cd opencode-server
bun install

# Local secrets (never commit this file)
cp .dev.vars.example .dev.vars
# then edit .dev.vars: ADMIN_TOKEN + at least one provider key

bun run dev          # http://localhost:8787
```

Open the printed URL: paste the admin token, create a key, done.

### Upstream providers

Providers turn on automatically when their key is present:

| Provider   | Secret                | Default base URL                            |
| ---------- | --------------------- | ------------------------------------------- |
| OpenAI     | `OPENAI_API_KEY`      | `https://api.openai.com/v1`                 |
| OpenRouter | `OPENROUTER_API_KEY`  | `https://openrouter.ai/api/v1`              |
| Nous       | `NOUS_API_KEY`        | `https://inference-api.nousresearch.com/v1` |
| Groq       | `GROQ_API_KEY`        | `https://api.groq.com/openai/v1`            |
| Workers AI | `CLOUDFLARE_ACCOUNT_ID` + `CLOUDFLARE_API_TOKEN` | Cloudflare AI gateway |

Override `OPENAI_BASE_URL` for an OpenAI-compatible local server such as Ollama or vLLM, or
declare everything explicitly with the `PROVIDERS` secret:

```json
[{ "id": "local", "baseUrl": "http://127.0.0.1:11434/v1", "apiKey": "none", "models": ["qwen3-coder"] }]
```

### Model catalog

`src/catalog.ts` holds the model ids `/v1/models` advertises. Regenerate it with:

```bash
bun run sync:models          # rewrites src/catalog.ts
bun run sync:models --check  # fails if it is stale (use in CI)
```

It pulls from [models.dev](https://models.dev/api.json) — the same catalog opencode reads — for
OpenAI and OpenRouter, plus the Nous inference API (Nous has no models.dev entry). A provider only
appears once its key is set, and `models` in `PROVIDERS` overrides the generated list.

### Routing

1. An **exact** model id in a provider's catalog wins, so `openrouter/auto` stays whole.
2. Otherwise `<provider>/<model>` strips the prefix when `<provider>` is a configured provider,
   so `openai/gpt-4o` reaches OpenAI as `gpt-4o`.
3. Otherwise the provider whose catalog lists the id.
4. Otherwise `DEFAULT_PROVIDER` (default `openai`).

### Deploy to Cloudflare

```bash
bunx wrangler d1 create opencode-server        # copy the printed database_id
# put that id in wrangler.jsonc -> d1_databases[0].database_id
bunx wrangler d1 execute opencode-server --remote --file=./schema.sql
bunx wrangler secret put ADMIN_TOKEN
bunx wrangler secret put OPENAI_API_KEY        # repeat per provider
bun run deploy
```

The dashboard is the Worker's URL; `/v1` is the API.

## Using it from opencode

Generate this from the dashboard's **opencode config** tab, or write it yourself:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "opencode-server": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "opencode-server",
      "options": { "baseURL": "https://<your-worker>/v1", "apiKey": "sk-oc-…" },
      "models": { "gpt-4.1-mini": { "name": "GPT-4.1 mini" } }
    }
  }
}
```

## API

Admin routes need `x-admin-token: <ADMIN_TOKEN>` (or `Authorization: Bearer <ADMIN_TOKEN>`).

| Method | Path                    | Purpose                                  |
| ------ | ----------------------- | ---------------------------------------- |
| GET    | `/api/me`               | Validate the admin token                 |
| GET    | `/api/keys`             | List keys                                |
| POST   | `/api/keys`             | `{ name?, rateLimitRpm?, monthlyTokenBudget? }` → `{ key }` |
| POST   | `/api/keys/:id/revoke`  | Revoke a key                             |
| GET    | `/api/usage?days=7`     | Totals by key, model and day             |
| GET    | `/api/models`           | Providers and their models               |
| GET    | `/healthz`              | Liveness + which providers are configured |

Client routes need `Authorization: Bearer sk-oc-…` and are OpenAI-compatible, so any OpenAI SDK
works by pointing `baseURL` at `https://<your-worker>/v1`.

## Notes

- Plaintext keys are returned once, at creation; only hashes are stored.
- Usage rows are written after the response is sent (`waitUntil`); streaming usage is read from the
  upstream's trailing `usage` chunk when the provider sends one.
- `wrangler.jsonc` ships a placeholder `database_id` — local dev ignores it, remote deploy needs
  your real id.
